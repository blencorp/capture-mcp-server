title: Self-host
description: Run the server on your computer over stdio or loopback HTTP, or host it with Docker or Railway for other people.
---

The server is not published to npm. Run it from a checkout of the
[repository](https://github.com/blencorp/capture-mcp-server), which needs Node.js 24.11 or later (or
26) and [pnpm](https://pnpm.io/) 12:

```bash
git clone https://github.com/blencorp/capture-mcp-server.git
cd capture-mcp-server
pnpm install --frozen-lockfile
pnpm build
```

Pick the mode by who uses it.

| Mode | Who it serves | Whose keys | How to start it |
| --- | --- | --- | --- |
| stdio | You, in a desktop assistant | Yours, from the environment | `node dist/server.js` |
| Local HTTP | You, on your computer | Yours, from the environment | `MCP_TRANSPORT=http MCP_ALLOW_INSECURE_HTTP=true node dist/server.js` |
| Hosted HTTP | Many people | Each person's own, entered when they connect | `MCP_TRANSPORT=http MCP_REQUIRE_OAUTH=true node dist/server.js`, with the settings below |

SAM.gov, Tango, and HigherGov keys are personal. The server never answers one person with another's
key, and a hosted server never uses a key from its own environment for a caller.

## stdio

Your assistant starts the server and talks to it over standard input and output. Add it to the
assistant's MCP configuration (here, the format of Claude Desktop's `claude_desktop_config.json`),
with the keys you have:

```json
{
  "mcpServers": {
    "capture": {
      "command": "node",
      "args": ["/path/to/capture-mcp-server/dist/server.js"],
      "env": {
        "SAM_GOV_API_KEY": "your-sam-gov-key",
        "TANGO_API_KEY": "your-tango-key",
        "HIGHERGOV_API_KEY": "your-highergov-key"
      }
    }
  }
}
```

Only the tools whose key you set are listed. With no keys, the 7 reference and USAspending tools
work.

## Local HTTP

```bash
MCP_TRANSPORT=http MCP_ALLOW_INSECURE_HTTP=true PORT=8080 SAM_GOV_API_KEY=... node dist/server.js
```

There is no sign-in. The server binds to `127.0.0.1`, refuses any other `HOST`, and refuses a request
whose Host header is not loopback. A client may send its own keys in `X-Sam-Api-Key`,
`X-Tango-Api-Key`, and `X-Highergov-Api-Key` headers, which override the environment.

## Hosted HTTP

HTTP mode refuses to start without authentication. For other people, set `MCP_REQUIRE_OAUTH=true`,
and the server runs the OAuth flow that [Connect your assistant](/connect/) describes.

| Setting | What it does |
| --- | --- |
| `MCP_TRANSPORT` | `http`. The default, `stdio`, speaks over standard input and output. |
| `MCP_REQUIRE_OAUTH` | `true`. Required for hosting. |
| `OAUTH_TOKEN_SECRET` | The secret that seals tokens. Required. Generate one with `openssl rand -base64 48`. Changing it invalidates every token, unless you keep the old one in `OAUTH_TOKEN_SECRET_PREVIOUS` (see [Rotating the secret](#rotating-the-secret)). |
| `OAUTH_TOKEN_SECRET_PREVIOUS` | Retired secrets, separated by commas (at most three), that still open tokens but never seal them. Leave it unset except during a rotation. |
| `MCP_PUBLIC_BASE_URL` | The public HTTPS origin your clients use, such as `https://capture.example.com`. Required. |
| `OAUTH_ACCESS_TOKEN_TTL_SECONDS`, `OAUTH_REFRESH_TOKEN_TTL_SECONDS` | Token lifetimes. The defaults are 1 hour and 90 days, and the server refuses to start with more than 1 day and 90 days. A refresh token keeps its original expiry however often it is used. |
| `MCP_IP_RPS`, `MCP_IP_BURST` | The budget for `/mcp` requests from one client address (the OAuth endpoints have their own limits, counted the same way: 100 authorization requests and 50 token or revocation requests every 15 minutes, 20 registrations an hour): sustained requests per second (default 5) and the burst (default 20). A request over budget gets `429` with `Retry-After`. |
| `MCP_CLIENT_IP_HEADER` | The header your proxy overwrites with the client address. **On Railway set `x-real-ip`**: unset, every limiter counts the connection's address, which behind a proxy is the proxy, so all your users share one budget. Name only a header the proxy always sets itself, because a client could forge any other. The server does not use `X-Forwarded-For` or Express's `trust proxy`. IPv6 clients are counted per /64, and IPv4-mapped IPv6 as IPv4. |
| `MCP_ALLOW_INSECURE_HTTP` | `true` for the single-user mode above. Not for hosting. |
| `PORT`, `HOST` | The listening port, and address. Leave `HOST` unset when you host so that Node listens on IPv4 and IPv6. |

The server serves the landing page, the policy pages, and this documentation at `/docs`. The
landing page needs `dist/web`, which `pnpm build` makes, and the documentation needs the built site
in `docs-site/`, which only the Docker image makes: `node dist/server.js` from a plain checkout serves
no `/docs`. Put the server behind HTTPS. It limits each client address's `/mcp` requests itself, but
a proxy or platform should still absorb floods before they reach it.

### Rotating the secret

Tokens are sealed, not stored, so the secret is the only thing that can revoke them all. The
server keeps a ring of secrets: it seals new tokens with `OAUTH_TOKEN_SECRET` and opens tokens sealed
with it or with any secret in `OAUTH_TOKEN_SECRET_PREVIOUS`. Setting either variable needs a restart.

**Routine rotation** (nobody has to reconnect; registrations and tokens both follow the ring):

1. Generate a new secret with `openssl rand -base64 48`.
2. Set `OAUTH_TOKEN_SECRET` to it and `OAUTH_TOKEN_SECRET_PREVIOUS` to the old one, and restart.
   Existing tokens keep working, and every refresh seals the new tokens with the new secret.
3. Keep the old secret in `OAUTH_TOKEN_SECRET_PREVIOUS` for **180 days** after the rotation (after
   the last time it sealed anything), then remove it. That is how long a client registration lasts,
   and a client ID sealed under the old secret is only readable with it: dropping it earlier makes
   that client's refresh fail with `invalid_client` even when its token is still valid, and its
   owner has to connect again. The 90-day refresh token alone is not the deadline.

The list holds at most three previous secrets and each stays for 180 days, so rotate no more often
than every 60 days. A fourth secret is a startup error: wait for the oldest to expire first, or use
the emergency path.

**Emergency revocation** (a secret or a token leaked): set `OAUTH_TOKEN_SECRET` to a new value,
leave `OAUTH_TOKEN_SECRET_PREVIOUS` unset, and restart. Every registration and token stops working
at once and everyone connects again; that is the price of dropping a secret early. Do not list a leaked secret as a previous one, because anyone who has it
can forge tokens it opens. Rotate the keys with their sources too, since a leaked token held them.

The server can revoke a single token (`/revoke`), but only in that instance's memory: a restart, or
another instance, forgets it. Treat that as a courtesy to well-behaved clients and rotate the secret
when a token must be dead. A short access token (an hour) is what bounds the rest.

### Docker

The repository's `Dockerfile` builds the hosted image. It builds this site into the image, runs
`node dist/server.js` as an unprivileged user, and refuses to start without authentication:

```bash
docker build -t capture-mcp-server .
docker run --rm -p 8080:8080 \
  -e MCP_REQUIRE_OAUTH=true \
  -e OAUTH_TOKEN_SECRET="$(openssl rand -base64 48)" \
  -e MCP_PUBLIC_BASE_URL=https://capture.example.com \
  capture-mcp-server
```

### Railway

Railway builds the same `Dockerfile` from the repository root. Set the three variables in the service
settings, and `MCP_CLIENT_IP_HEADER=x-real-ip` so that the `/mcp` budget counts each client rather than Railway's proxy. The service itself (Dockerfile build, start command, the `/health` check with a 30-second
timeout, restart on failure up to three times, one replica, and the custom domain) is declared in
`.railway/railway.ts`, the only Railway settings file; Railway no longer reads `railway.toml`. Apply
changes to it with `railway config apply`. Secrets stay set in Railway, not in that file. The project
name, domain and region in it are BLEN's production values: change them for your own deployment, or
set the same health check, start command and restart policy in your service settings.

## Rules for every deployment

- **Run one replica.** The pacing queues, the cache, the budgets and the revocation list are in the
  server's memory. Two instances that share a key look like two clients to the source, and each
  keeps its own budgets. Registrations and tokens are sealed, so any instance with the same secrets
  accepts them.
- **Authentication is required.** HTTP mode refuses to start without OAuth or the loopback opt-in.
- **Guard `OAUTH_TOKEN_SECRET`.** Anyone who has it can open every token, and so every key sealed in
  one.
