title: Security
description: Where keys live, what the server does and does not do, and how to report a vulnerability.

The server calls public APIs with your keys, and it treats everything those APIs return as untrusted
text.

## Keys

- Your keys are sealed with AES-256-GCM inside the access and refresh tokens that the server gives
  your assistant. The sealing secret is the server's `OAUTH_TOKEN_SECRET`, held only in its
  environment. The server stores no key and has no database.
- The server opens a token for the request that carries it, uses the key for the one source a tool
  needs, and does not keep it.
- A key goes only to the source it belongs to, at that source's fixed address.
- No tool takes an API key as an argument, and a call that includes one is refused, so a key never
  passes through your assistant. The server adds your connection's key itself.
- The server does not check a key when you enter it, and it has no general redaction: an error
  carries the status and body a source sent. The HigherGov tools do not pass on the URLs in which
  HigherGov embeds the key. Rotate a key with its source if you think it leaked.
- A single token cannot be reliably revoked. The server remembers a revoked token only in memory,
  in one instance, so a restart forgets it. An access token lasts an hour, which bounds a leaked
  one. Rotate the key with its source to cut off a leaked token, or the operator can change the
  server's secret to invalidate every token at once (see [Self-host](/self-host/#rotating-the-secret)).

## Access

- Every tool is read-only: the server changes nothing at any source.
- Hosted access uses OAuth 2.1 with PKCE and dynamic client registration. Every `/mcp` request needs
  a valid bearer token. Provider-key headers never authenticate a caller: they only add the
  caller's own key for a source.
- Access tokens last an hour and refresh tokens 90 days, unless the operator sets shorter lifetimes. A refreshed token never outlives the 90 days of its first refresh token, nor the 180-day registration of the assistant it was issued to. A token must carry the `mcp:tools` scope.
- A hosted caller uses only keys it supplied. The server never uses a key from its own environment to
  answer one. On your own computer, over stdio or loopback HTTP, the environment keys are yours.
- Single-user HTTP (`MCP_ALLOW_INSECURE_HTTP`) refuses to listen on anything but loopback, and
  refuses a request whose Host is not loopback.
- `/mcp` gives each client address a budget (a burst of 20 requests, then 5 a second), and refuses
  the excess with `429`. The page where you enter your keys is served with a content security
  policy and is never cached. The MCP SDK's OAuth endpoints limit each address by default (100 authorization
  requests and 50 token or revocation requests every 15 minutes, and 20 registrations an hour).

## What the server does not do

- It runs no code that a model wrote: the tools take arguments, and nothing more.
- It does not download documents or files. A tool that lists documents returns their links.
- It does not store your questions or the answers.

## Report a vulnerability

Do not open a public issue. Open a
[private security advisory](https://github.com/blencorp/capture-mcp-server/security/advisories/new),
or write to opensource@blencorp.com. The full policy is in
[SECURITY.md](https://github.com/blencorp/capture-mcp-server/blob/main/SECURITY.md).
